## 9. Critical Issues Found During Audit (Action Required)

### 🔴 CRITICAL: Release build signed with debug keystore

**File:** `android/app/build.gradle` line 115
```gradle
release {
    signingConfig signingConfigs.debug  // ⚠️ DEBUG KEYSTORE IN PRODUCTION!
```

The production AAB is being signed with the **debug keystore**, not a proper release keystore. This is a **critical security and compliance issue**:

- Google Play may reject the upload if a previous version was signed with a different key
- The debug keystore is not secure — anyone can sign apps with it
- You **cannot change the signing key** after publishing without losing all installs and reviews (Play App Signing can help, but it must be set up before first upload)

**Action required:**
1. Generate a release keystore:
   ```
   keytool -genkey -v -keystore ipgm-release.keystore -alias ipgm -keyalg RSA -keysize 2048 -validity 10000
   ```
2. Add it to `build.gradle`:
   ```gradle
   signingConfigs {
       release {
           storeFile file('ipgm-release.keystore')
           storePassword 'YOUR_PASSWORD'
           keyAlias 'ipgm'
           keyPassword 'YOUR_PASSWORD'
       }
   }
   ```
3. Update the release build type: `signingConfig signingConfigs.release`
4. **Never commit the keystore file or passwords to git** — add to `.gitignore`
5. Alternatively, use **EAS credentials** (`eas credentials`) which manages signing keys securely in the cloud (recommended for Expo projects)

### 🔴 CRITICAL: RECORD_AUDIO permission declared but unused

**File:** `android/app/src/main/AndroidManifest.xml` line 7
```xml
<uses-permission android:name="android.permission.RECORD_AUDIO"/>
```

I searched the entire `src/` directory — **no audio recording code exists** (no `expo-av`, `expo-audio`, `Audio.Recording`, or `expo-speech`). This permission is unused.

**Impact:**
- Google Play's Data Safety form requires you to declare why you collect audio data — you'd have to lie or remove it
- Users see "Microphone" in the permission list on the store listing, which **reduces install conversion rate** (users are wary of apps requesting microphone access)
- Apple may reject the iOS app for unused permissions

**Action required:** Remove `RECORD_AUDIO` from `app.json` permissions array and from `AndroidManifest.xml`. If using Expo managed workflow, removing it from `app.json` and running `expo prebuild --clean` will regenerate the manifest.

### 🟡 WARNING: SYSTEM_ALERT_WINDOW permission may be unnecessary

**File:** `android/app/src/main/AndroidManifest.xml` line 8
```xml
<uses-permission android:name="android.permission.SYSTEM_ALERT_WINDOW"/>
```

This permission allows drawing over other apps (screen overlay). It's typically only needed for screen recording, floating widgets, or chat heads. For a PG management app, this is likely unnecessary and can:

- Trigger additional review scrutiny on Google Play
- Show a scary permission prompt to users
- Some Android versions show a warning about overlay apps

**Action required:** Verify if any feature uses overlay windows. If not, remove this permission. (Note: Some React Native libraries request this automatically — check if `expo-notifications` or any debug tool requires it.)

**File:** `android/app/build.gradle` lines 95-96
```gradle

```

These are fine for a first release. However:
- If the app is **already published**, you **must increment `versionCode`** (e.g., to 2) for every new upload — Google Play rejects uploads with the same or lower versionCode
